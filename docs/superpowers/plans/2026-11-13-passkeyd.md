# passkeyd Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user daemon that appears as a USB FIDO2 security key and signs WebAuthn logins with Bitwarden passkeys after an account pick (if >1) and a fingerprint check.

**Architecture:** `/dev/uhid` virtual HID device → CTAPHID framing (worker thread, keepalive, cancel) → CTAP2 authenticator that asks a `Vault` for matching credentials and an `Approver` (zenity + fprintd-verify) for the pick and fingerprint. The vault reads Bitwarden via the `bw` CLI with a session key kept in the Secret Service keyring.

**Tech Stack:** Python 3 (system), `fido2` 2.2.1 (only `fido2.cbor`), `cryptography`, `secretstorage`, `zenity`, `fprintd-verify`, `bw` CLI, stdlib `unittest`, systemd user unit.

**Spec:** `docs/superpowers/specs/2026-11-13-passkeyd-design.md`

## Global Constraints

- No pip installs: only system Python packages already present (`fido2`, `cryptography`, `secretstorage`). Tests use stdlib `unittest` (`python3 -m unittest`).
- Run as `python3 -m passkeyd <run|setup|status>` from the repo root; no packaging.
- `BW_SESSION` and the master password are passed to `bw` via environment only, never argv; never logged; never written to disk except via Secret Service.
- Private keys live only in memory.
- getInfo: versions `["FIDO_2_0"]`, options `{"rk": True, "up": True, "uv": True, "plat": False}`, maxMsgSize 1200, no clientPin.
- Assertion authData flags: fingerprint-approved = `0x1D` (UP|UV|BE|BS); silent `up: false` = `0x18` (BE|BS).
- Discoverable request (empty allowList) responses carry key `6` (`userSelected`) = `True`.
- `makeCredential` (including the empty-`pinUvAuthParam` probe) → `0x27` OPERATION_DENIED immediately. No match → `0x2E` NO_CREDENTIALS immediately.
- Fingerprint: up to 3 attempts, then `0x27`. Client CANCEL → `0x2D` KEEPALIVE_CANCEL.
- Vault resync every 600 s, plus on no-match at most once per 60 s. Session locked/invalid → wipe in-memory credentials.

## Review Focus

1. App cancels while the picker or fingerprint prompt is open → dialog/`fprintd-verify` processes are killed and the response is `0x2D`, no orphan windows. (Task 4, Task 3)
2. A second CBOR request arrives on any channel while one is in progress → CTAPHID error `0x06` CHANNEL_BUSY, first request unaffected. (Task 2)
3. Daemon starts with no stored session or a locked keyring → it still creates the device, answers `0x2E`, and shows a notification telling the user to run `passkeyd setup`. (Task 3, Task 5)
4. A vault item with an unparsable `keyValue` or non-P-256 key → that credential is skipped with a log line; all others still load. (Task 3)
5. `fprintd-verify` fails because the device is claimed/busy or no finger enrolled → counted as a failed attempt with a notification, never a hang. (Task 4)

### Task 2: uhid device and CTAPHID transport

**Files:**
- Create: `passkeyd/uhid.py`, `passkeyd/ctaphid.py`
- Test: `tests/test_ctaphid.py`

**Interfaces:**
- Produces (`uhid.py`): `class UhidDevice` with `open() -> None` (creates device: name `"passkeyd virtual key"`, bus 0x03, vendor 0x1209, product 0x5070, FIDO report descriptor from the spike), `read_output() -> bytes | None` (blocking; returns one 64-byte output report with any leading report-id byte stripped, None for non-output events), `send_input(report: bytes) -> None`, `close() -> None`. Raises `PermissionError` with the spike's message when `/dev/uhid` is not accessible.
- Produces (`ctaphid.py`): `class CtapHid(send: Callable[[bytes], None], handle_cbor: Callable[[bytes, threading.Event], bytes])` with `on_report(report: bytes) -> None`. CBOR requests run on a worker thread; while running, send KEEPALIVE (`0xBB`, payload `b"\x02"`) every 100 ms; `CANCEL` (`0x91`) on the busy channel sets the request's Event. INIT/PING/WINK as in the spike, capabilities `0x0D`. Error codes: `ERR_INVALID_CMD=0x01`, `ERR_INVALID_SEQ=0x04`, `ERR_CHANNEL_BUSY=0x06`.

### Task 3: Bitwarden vault and keyring session

**Files:**
- Create: `passkeyd/vault.py`, `passkeyd/session.py`
- Test: `tests/test_vault.py`

**Interfaces:**
- Produces (`session.py`): `load_session() -> str | None` (Secret Service, attributes `{"application": "passkeyd"}`; returns None if absent or the collection is locked), `save_session(token: str) -> None` (label `"passkeyd Bitwarden session"`).
- Produces (`vault.py`):
  - `decode_credential_id(s: str) -> bytes`: `"b64.<x>"` → base64url-decode `<x>`; UUID string → `uuid.UUID(s).bytes`; otherwise base64url-decode.
  - `parse_items(items: list[dict]) -> list[Credential]`: one `Credential` per `login.fido2Credentials` entry; `keyValue` is base64url PKCS8; `userHandle` base64url; `counter` int of string; `item_name = item["name"]`; skip (and log) any entry that fails to parse or isn't P-256.
  - `class VaultLocked(Exception)`
  - `class BwRunner(session_provider: Callable[[], str | None], bw: str = "bw")` with `run(args: list[str], extra_env: dict | None = None) -> bytes`; sets `BW_SESSION` in env; raises `VaultLocked` when no session or `bw` output/exit indicates locked ("Vault is locked", "not logged in", non-zero exit on `list`).
  - `class Vault(runner: BwRunner, clock: Callable[[], float] = time.monotonic, on_locked: Callable[[], None])` implementing `VaultLike.find` plus `sync() -> None` (`bw sync` then `bw list items`; on `VaultLocked` wipe credentials and call `on_locked`) and `maybe_resync(no_match: bool) -> None` (periodic 600 s; no-match path at most once per 60 s).
  - `setup_session(password: str, runner_bw: str = "bw") -> str`: `bw unlock --raw --passwordenv PASSKEYD_PW` with `PASSKEYD_PW` in env; returns the token.

### Task 4: Approver — picker, fingerprint, prompts

**Files:**
- Create: `passkeyd/approver.py`
- Test: `tests/test_approver.py`

**Interfaces:**
- Consumes: `Credential`, `Cancelled` (Task 1).
- Produces: `class Approver(spawn: Callable[[list[str]], subprocess.Popen] = subprocess.Popen)` implementing `ApproverLike`; plus `notify(text: str) -> None` (`notify-send passkeyd <text>`, fire-and-forget) and `ask_password(text: str) -> str | None` (`zenity --password`).
  - `pick`: `zenity --list --title "Sign in to <rp_id>" --column "#" --column "User" --column "Name" --column "Vault item" --column "Created" --hide-column 1 --print-column 1`; returns selected credential, None on cancel/close.
